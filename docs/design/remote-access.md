# 远程接入规划

当前支持本地 IPC、显式 TCP 和[手动证书 mTLS](../mtls.md)。配对、设备撤销、账号中心与 Relay 尚未实现。

## 执行与授权边界

一个 BAS 实例是一份共享执行环境。获准客户端共享会话、Agent 配置和模型登录状态；
服务使用自己的系统用户身份运行，不按远程账号切换系统用户，也不提供实例内多租户隔离。
客户端可以连接多个实例。BAS 接入认证与 Agent 自身登录分别管理。

## 实施顺序

| 阶段 | 范围 |
| --- | --- |
| 独立远程接入 | mTLS、设备配对与撤销、多服务连接、断线续传；要求网络可直连 |
| 账号中心 | 官方托管或自部署；管理账号、实例归属、设备发现和授权；业务流量仍直连 |
| Relay | 直连不可用时提供中继，复用设备身份与授权，保持端到端加密 |

本地同用户 IPC 保持免配对。账号中心和 Relay 都不是本机使用的前置条件。

## 配对

服务端主动开启配对并生成一次性邀请；客户端扫码、粘贴链接或导入二维码，
在本机生成密钥，核对服务端身份后注册设备，保存连接配置。

邀请包含格式版本、可达的配对地址、服务公钥指纹、一次性授权凭据和可选显示名称。
不携带设备私钥或模型凭据，不写入诊断日志。建议有效期五分钟，成功注册即消费，支持提前取消；
并发消费和响应丢失后的重试语义需在实现时确定。

配对入口通过服务端 TLS 和邀请认证，业务入口要求已授权设备的 mTLS 身份。
配对与业务入口必须绑定同一可信服务身份，不能为配对放开业务 RPC。
二维码只解决配置与信任，不解决网络可达性。

设备撤销须阻止新连接，并明确处理已有连接和长流；撤销连接不等于取消服务端任务。

## 账号中心

每个实例归属一个账号；账号身份包含账号中心身份。首版不提供团队、跨账号共享或联邦。
使用成熟 OAuth/OIDC 实现：浏览器采用授权码与 PKCE，无浏览器设备采用设备授权。
账号中心批准设备登记与访问，设备密钥留在本地；不要求同时增加另一套业务连接认证。

账号中心离线不终止既有 Agent 任务。缓存授权有效期、撤销传播与离线新连接策略需要一起确定。
Relay 只改变网络路径，不取得 Agent 凭据或会话内容，也不改变会话与提交协议。
