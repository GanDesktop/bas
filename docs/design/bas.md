# BAS 架构

[架构图](../server-architecture.html)

客户端连接 BAS，BAS 作为 ACP 客户端连接外部 Agent。这是两条独立连接，各自拥有请求 ID 和连接生命周期。

| 参与方 | 拥有的状态与职责 |
| --- | --- |
| 客户端 | 连接配置、界面、已读位置；提交输入、观察输出、回答交互请求 |
| BAS | 工作区、公开会话 ID、执行生命周期、提交凭据、历史与订阅、Agent 接入 |
| Agent | 模型调用、工具执行和自身可恢复的对话上下文 |

## 会话与执行

BAS 将公开会话 ID 映射到 Agent 的会话 ID。多个客户端可同时观察和操作同一会话，没有主控客户端。
客户端断开只移除该连接的订阅和回调投递，不取消已受理的执行，也不替 Agent 回答待处理请求。
同一交互可以投递给多个支持它的客户端，BAS 只转交第一个有效回答。

提交凭据表示输入已被 BAS 接受，不表示 Agent 已执行成功。客户端从历史与 ACP 观察流构建对话，
不因收到凭据再插入一条消息。请求 ID 用于关联响应，事件游标用于回放，两者不能混用。

## 状态与观察

- `ObserveAcp`：Agent 协议请求、响应和通知，驱动会话内容与交互。
- `Attach`：BAS 管理事件，包含会话状态、标题、归档、工作区和运行故障。
- 历史查询：按需读取已提交的内容窗口和上下文，返回用于衔接实时订阅的高水位。

两条观察流分别推进游标。Agent 返回的请求错误属于 ACP；进程丢失、存储失败或 BAS 重启属于管理状态，
不能伪造为 Agent 响应。历史中的权限请求不能重新执行为回调。

## 持久化与恢复

SQLite 保存会话元数据、提交凭据和事件；成功提交后才确认和广播。内存模式仅保留有界历史。
BAS 历史和 Agent 上下文独立：恢复对话需要 Agent 支持 `session/load` 或 `session/resume`，
不能用新建空会话代替恢复。已有会话的 load 回放不重复写入历史。
重启前未完成的回合记为中断，不自动重发输入或工具操作。

归档保留会话与历史，删除移除 BAS 记录；工作区删除不删除用户项目文件。
接口、失败语义和分页约定见 [RPC](../rpc.md)。

## 运行边界

一个服务实例提供共享执行环境，Agent 以服务进程的系统用户身份运行。
多个监听入口访问同一份状态。接入认证、工具权限审批和操作系统隔离是不同职责。

`Server` 从配置准备存储、会话注册表、可选 Agent 管理器及监听入口；`run` 返回可取消的 Handle。
退出时停止接收工作并关闭 Agent、订阅和后台任务，宽限期由 `--shutdown-grace` 指定。
